# Nanobug V2 使用指南

Rust 原生字符网格编辑器的基础框架。GPUI 负责原生窗口与 GPU 绘制，Rust 自己实现文本模型和简易 Vim 操作。

初始界面只有左侧文件管理器和右侧编辑区。全窗口共享平滑光标，逻辑焦点立即切换，输入法候选位置跟随逻辑输入点。背景采用 **84% 不透明度**（约 16% 透明），文字独立保持不透明；Windows 使用系统模糊材质，其他平台的材质表现尚未验收。

内部面板参考 Glass Editor Demo 的网格样式，使用 `╭─╮╰─╯` 字符圆角、边框内标题及焦点颜色。顶部项目栏用 `|` 分隔项目，以薄荷绿色块标记当前项目。两侧的 `←2` 或 `4→` 表示被隐藏的项目数量。Windows 窗口可从项目栏拖动。底部状态栏占一行，左侧显示模式和文件名，输入命令、搜索或显示反馈时使用同一区域。正文使用独立行号分隔线。

## 运行

在项目根目录执行 `cargo run --locked`。已有本地构建或已缓存依赖时，也可运行 `Start-Nanobug.ps1`。

在依赖已缓存时运行 `Build.ps1`，可生成 `dist/Nanobug.exe` 和 `dist/启动 Nanobug.cmd`。双击启动脚本会默认打开本项目。直接运行 EXE 时默认打开工作目录，也可传入多个目录或文件路径来打开项目。

```powershell
cargo run --locked -- .
```

左侧读取真实文件系统，右侧初始打开项目 README.md；没有 README 时显示空白缓冲区。双击文件或在管理器按 Enter 打开，先前文件的未保存内容会保留在内存，再次打开可恢复。

### 界面语言

在编辑区普通模式或文件管理器中，用 `<leader>L` 打开 `language` 弹层，实际按键是 `Space`、`Shift+l`。用 `↑/↓` 或 `k/j` 移动，按 `Enter` 或点击 `apply` 应用，也可直接点击语言。按 `Esc`、点击 `close` 或点击弹层外取消。

选择立即应用到本次运行中的所有项目。Nanobug 默认以英文启动。在 PowerShell 中设置 `NANOBUG_LANG` 后启动，可将初始语言设为简体中文。

```powershell
$env:NANOBUG_LANG = 'zh-CN'
.\Start-Nanobug.ps1
```

将 `NANOBUG_LANG` 设为 `en` 或移除变量后，重新启动即可恢复英文。英文和简体中文的 TOML 资源位于 `assets/i18n/`，随可执行文件内嵌。

## 基础操作

`<leader>` 默认使用空格键。在编辑区普通模式或 Explorer 中按下后，右下角会列出当前层级可用的后续键。带 `+` 的条目进入子分组，标题用 `→` 依次连接 `Leader` 和已输入的各级分组键，例如 `Leader → q`。`Backspace` 或底部的 `back` 返回上一级，在首层回退会关闭提示。`Esc` 或底部的 `close` 取消整个序列。

| 区域 | 操作 |
| --- | --- |
| 项目切换 | `Alt+h` 或 `Alt+k` 切到上一个项目，`Alt+l` 或 `Alt+j` 切到下一个。各项目保留文件树、缓冲区和窗格焦点 |
| 项目排序 | `Ctrl+Alt+h/k` 向左移动当前项目，`Ctrl+Alt+l/j` 向右移动。`Ctrl+Alt+Home/End` 移到最前或最后 |
| 关闭项目 | 在编辑区普通模式或 Explorer 中，`<leader>qq` 关闭当前项目，`<leader>qa` 关闭所有项目并退出 |
| 窗格切换与关闭 | 普通模式下，`Ctrl+h` 聚焦左侧 Explorer，`Ctrl+l` 聚焦右侧编辑区并可恢复已关闭的编辑区。`Ctrl+j/k` 对应下 / 上方向，有目标窗格时切换。Explorer 按 `q` 关闭，编辑区按 `Alt+Esc` 关闭。鼠标靠近窗格或弹窗右上角的关闭区时，会显示可点击的 `[Esc]` |
| 打开 Explorer | 普通模式下按 `<leader>e`（先按 `Space`，再按 `e`），打开并聚焦左侧 Explorer |
| 快捷键帮助 | Vim 模式下按 `?` 打开当前窗格的帮助。`h` 查看区域快捷键，`l` 查看全局快捷键。浏览时按 `q` 或 `Esc` 关闭 |
| 文件管理器 | `j k` 移动，`h` 折叠，`l` 或 Enter 打开文件或切换目录，`gg G` 跳到首末项，`zz zt zb` 定位视口。鼠标单击选中，双击激活，F5 刷新 |
| 管理器文件操作 | `s` 标记多项，`c x` 复制或剪切，`v` 粘贴，`z Z` 撤销或重做粘贴 |
| 分栏宽度 | 鼠标拖动垂直分隔线 |
| 指针编辑 | 点击定位，拖动进入字符选择，滚轮纵向滚动，Shift+滚轮横向滚动编辑区 |
| 光标动效 | F6 切换预设，Shift+F6 反向切换，F7 重载项目光标配置 |
| 插入模式 | `i a I A o O`，Esc / Ctrl+[ 回到普通模式 |
| 插入编辑 | 方向键、Backspace、Delete、Enter、Tab、Ctrl+w、Ctrl+u；Ctrl+v 粘贴系统剪贴板 |
| 光标移动 | `h j k l w b e 0 ^ $ gg G`，支持数字次数和 `3G` |
| 删除/修改 | `x s dd dw de d$ D cw cc C`，支持 `2dd`、`d2w` 等 |
| 复制/粘贴 | `yy y{移动}`、`p P`，共享一个未命名寄存器 |
| 选择 | `v V`，移动后 `y d x c`，Esc 取消 |
| 撤销/重做 | `u` / Ctrl+r，一次插入会话为一个撤销单元 |
| 行操作 | `J` 合并下一行 |
| 搜索 | `/文本` + Enter，`n N` 循环搜索（字面文本） |
| 保存 | `:w`、`:w 文件名`、Ctrl+s |
| 打开 | `:e 文件名` 在当前项目打开文件，`:e 目录` 打开或切换到该项目。支持绝对路径和相对项目根目录的路径 |
| 退出 | `:q`、`:q!`、`:wq`、`:x` |

在快捷键帮助中，`j/k` 或上下方向键移动选中行，也可用鼠标点击。`5j` 向下移动 5 行，`5k` 向上移动 5 行。`gg`、`G`、`3G` 跳到首行、末行和指定行，`PageUp/PageDown` 移动一页。列表平滑滚动，光标到可滚动边缘的第 4 行时，再移动会带动列表。

按 `/` 用搜索框覆盖列表底部一行，实时按快捷键描述筛选。按 `Enter` 保留筛选并继续浏览，按 `Esc` 取消本次输入，也可点击对应按钮。`n/N` 浏览下一条或上一条匹配。切换区域和全局时保留筛选词，重新打开帮助时从当前窗口的完整列表开始。

Explorer 使用内置的 Material Icon Theme 深色图标。文件按名称或后缀匹配，未知类型使用通用文件图标。目录按名称匹配，并随展开和收起切换图标。[Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme)

`<leader>qq` 检查当前项目的未保存修改。关闭后优先选中右侧项目，位于末尾时选中左侧项目。关闭最后一个项目会退出。

`<leader>qa`、窗口关闭和 `:q` 都会检查所有项目的未保存修改，并在底部指出需要保存的项目。`:q!` 明确放弃所有缓冲区的未保存修改。保存时先写入同目录的临时文件，再替换原文件。

管理器将文件粘贴到当前目录项，或当前文件的父目录。同名目标会阻止粘贴。单按 `z` 等待 350 毫秒后撤销，供 `zz`、`zt`、`zb` 输入第二键。每次粘贴作为一条历史，最多保留 10 条，编辑相关文件会使对应记录失效。

普通模式和选择模式直接接收命令按键，中文输入法不会拦截 `i`、`:`、`hjkl` 等操作；插入、搜索和命令行模式继续使用原生文本输入法。

## 光标与滚动动效

启动时使用带渐隐残像的“余晖”。F6 可在“流体”“弹性”“余晖”“涟漪”间循环。四种预设使用同一套光标阶段。

在项目根目录编辑 `cursor-effects.toml`，按 F7 应用。优先级从低到高为内置预设、`[stages.<阶段>]` 和 `[presets.<预设>.<阶段>]`。预设键为 `fluid`、`elastic`、`afterglow`、`ripple`。填写 `effects` 会替换该阶段继承的列表，空数组会清空。

| 轨道 | 阶段键 |
| --- | --- |
| 主流程 | `place`、`idle`、`target`、`prepare`、`travel`、`approach`、`arrive`、`settle`、`post_move` |
| 区域滚动 | `scroll_start`、`scroll_follow`、`scroll_settle`、`scroll_end` |
| 显隐 | `show`、`hide` |

效果项的 `kind` 可选 `droplet`、`stretch`、`rebound`、`afterimage`、`ripple`、`breath`、`blink`、`scale`、`glow`、`fade`、`scroll_drag`。通过 `strength` 调强度，通过 `delay_ms`、`duration_ms`、`repeat_ms` 和 `count` 调播放节奏。阶段内的重复效果在离开时停止，瞬时事件的重复需要指定次数。有限单次效果可用 `finish = true` 让它在阶段退出后播完。未指定时长的视觉脉冲为 300ms，形状和运动修饰默认随阶段保持。`afterimage` 的时长同时决定残像衰减长度，默认每个残像 180ms。

`prepare.duration_ms` 和 `prepare.insert_ms` 分别设置块光标和细插入光标的准备时间，`post_move.duration_ms` 设置驻留时间。可用 `response_ms` 调行进、收束或滚动拖尾的响应时间。`ripple` 支持 `target = "cursor"`、`"nearby_text"` 或 `"both"`，可通过 `radius_px` 和 `text_offset_px` 调波及范围和字形位移。模板包含可直接启用的组合。

管理器和编辑区都采用连续平滑滚动，停稳时对齐整行或整列。编辑区光标向左右边缘移动时，正文从第 8 个显示列附近开始跟随，行号栏保持横向固定。正文在固定字符边框内裁剪。光标头部随所属正文平移，滚动速度驱动主轮廓的拖尾。静止延时和脉冲间隔使用定时唤醒，持续形变时逐帧刷新。

运行 `cargo run --offline --example animation_trace` 可导出实际动效模型的比较数据。可选用 Pillow 执行 `python tools/render_cursor_preview.py test-output/cursor-effects.csv test-output/cursor-effects.gif` 生成预览；Python/Pillow 只用于离线制品，不是编辑器运行依赖。

## 当前范围

这是简易 Vim 操作集，不是完整 Vim：没有宏、命名寄存器、文本对象、点号重放、正则替换、Vimscript 或 Vim 插件兼容。没有外部 Neovim 进程或运行时依赖。

目前支持 UTF-8 文本，打开大小上限为 16 MiB，保留已有 BOM、LF/CRLF 与 Tab。文本使用 String 和有容量上限的快照撤销，尚未实现面向大文件的增量结构。输入法接入了本地预编辑与提交，仍需覆盖各输入法的人工验收。

基础框架未加入插件系统、语言服务或语法高亮。当前固定 GPUI 0.3.10，本机 Windows 是已构建和交互验证的平台。

## 源码组织

目录先表达功能归属，再在各功能内按职责拆分。`src` 根目录只保留程序入口和库入口：

```text
src/
├── main.rs                    # 原生程序入口，调用 app::run
├── lib.rs                     # document、vim、animation 的库入口
├── app/                       # 启动参数、资源注册和原生窗口创建
├── grid/                      # 网格窗口体系
│   ├── workspace/             # 布局、焦点、输入路由和跨窗口协调
│   ├── windows/
│   │   ├── editor/            # 编辑区域
│   │   │   ├── mod.rs         # EditorWindow：缓冲区和编辑输入状态
│   │   │   ├── buffer.rs      # 单个缓冲区的视口和显示文本
│   │   │   ├── commands.rs    # 打开、保存和文件路径同步
│   │   │   ├── input.rs       # 编辑按键和 Vim 调用
│   │   │   ├── pointer.rs     # 正文命中和鼠标选择
│   │   │   ├── view.rs        # 边框、行号和正文帧
│   │   │   └── shortcuts.rs   # 编辑区域帮助内容
│   │   ├── manager/           # 文件管理器
│   │   │   ├── mod.rs         # ManagerWindow：目录树、滚动和文件操作状态
│   │   │   ├── tree.rs        # 目录树和标记
│   │   │   ├── transfer.rs    # 复制、剪切、粘贴及撤销历史
│   │   │   ├── commands.rs    # 文件操作及路径变更通知
│   │   │   ├── input.rs       # 导航和文件操作按键
│   │   │   ├── pointer.rs     # 行选择和双击打开
│   │   │   ├── icons.rs       # 文件名到图标的匹配规则
│   │   │   ├── view.rs        # 目录树帧和文件名预览
│   │   │   └── shortcuts.rs   # 管理器帮助内容
│   │   ├── help/              # 快捷键帮助：状态、输入、布局和背景缓存
│   │   └── frame.rs           # 窗口绘制共享的布局与选中状态
│   └── render/                # 字符帧、网格几何、缓存排版和全局光标绘制
├── vim/                       # 独立 Vim 编辑模型
│   ├── mod.rs                 # 每个缓冲区的模态状态及对外接口
│   ├── mode.rs                # 模式和状态标签
│   ├── input.rs               # 语义按键、计数和插入输入
│   ├── motions.rs             # 字素、词和行移动
│   ├── operators.rs           # 复制、删除、修改和粘贴
│   ├── commands.rs            # Ex 命令和字面搜索
│   └── register.rs            # 未命名寄存器
├── document/                  # 文本、文件读写、修订和撤销历史
├── animation/                 # 光标与连续滚动的时间模型
└── ui/                        # 通用字体测量、图标缓存、主题、按键归一化和 IME 预编辑
```

`EditorWindow` 拥有打开的缓冲区、活动文档、寄存器、输入法预编辑和鼠标选择；`ManagerWindow` 拥有目录树、标记、文件操作历史和管理器滚动；`HelpWindow` 拥有快捷键分组、筛选、选中行、滚动和背景缓存。各窗口在自己的目录中处理局部输入并生成字符帧。工作区持有这些窗口，并负责布局、焦点、原生事件桥接、公共绘制层和跨窗口动作。例如，管理器返回文件移动通知后，工作区让编辑区域同步缓冲区路径；编辑文档后，工作区使相关文件操作历史失效。

依赖方向为 `app → grid`，`grid::workspace → grid::windows + grid::render`，具体窗口使用 `vim`、`document`、`animation` 和通用 `ui` 能力。`vim` 只处理编辑语义并返回保存、打开、关闭等动作，由工作区执行；它不依赖 GPUI、网格窗口或原生按键类型。`document` 不依赖 Vim。通用 `ui` 和 `grid::render` 不依赖具体窗口或工作区；管理器负责图标匹配，通用 `ui::icons` 负责 SVG 绘制和缓存。

新增网格窗口放在 `grid/windows/<功能>/`，将它的状态、输入、视图和专属辅助代码放在一起；窗口间确实共用的能力才提升到 `grid` 或 `ui`。修改 Vim 行为时进入 `vim/` 对应模块。`main.rs` 只调用应用入口，`lib.rs` 只声明库模块，不将实现文件堆回根目录，也不通过 `#[path]` 绕过目录结构。

模块入口只导出调用方需要的类型和函数；网格内部协作限制在 `pub(in crate::grid)`，模块内部实现保持私有。库调用方通过 `nanobug::document`、`nanobug::vim` 和 `nanobug::animation` 使用模型。局部测试随功能放置，网格窗口协作测试在 `grid/windows/tests.rs`，跨库行为测试在 `tests/`，动效示例在 `examples/`。嵌入资源以 `CARGO_MANIFEST_DIR` 定位，绘制缓存不持有可编辑文档副本。
