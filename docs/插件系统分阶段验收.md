# 插件系统分阶段验收

整理日期：2026-11-12。依据：[插件系统初版实现规格](插件系统初版实现规格.md)。

**独立工作区已有 Windows 试用版，68 项中已通过 62 项。Windows 三组热启动均达标。** 本页按整条验收条件勾选。六项的最新缺口见下方逐项复验记录。[Release 验证记录](research/2026-11-12-plugin-release-verification.md#2026-11-13-平台与启动补验) · [实机验收步骤](插件系统实机验收.md) · [P0 验证报告](research/2026-11-12-plugin-p0-results.md)

## 1. 交付顺序

| 阶段 | 用户能看到的完整结果 | 必要前置 | 为什么单独验收 |
| --- | --- | --- | --- |
| P0 验证关键路径 | 一个测试插件能按条件准备、显示可输入文字，故障后恢复，并测出启动与交互成本 | 无 | 先验证跨进程绘图、输入确认、运行中断等关键假设，避免在未验证基础上扩建 |
| P1 安装与运行基础 | 从本地 ZIP 安装一个真实兼容插件，可查看身份/状态并在独立进程运行 | P0 | 形成真正的安装、身份、兼容和运行闭环；试验加载不能替代正式安装 |
| P2 规则与项目生命周期 | 修改规则、Apply、自动判断；重开保留未应用内容，关闭项目释放独占资源 | P1 | 配置、判断和资源所有权共同决定用户实际体验 |
| P3 完整 UI SDK 与输入恢复 | 自绘/网格插件可使用完整目标绘图、光标、IME，并保护输入与草稿 | P2 | 图形、输入及资源代次必须一起正确，不能分别通过就宣称完成 |
| P4 编辑与工具能力 | 插件能提供语言结果、格式化、跨文件修改，并使用受管解析/工具 | P2、P3 | 需要版本化正文、输入保护和统一预览；覆盖真实外部操作风险 |
| P5 设置与开发工具 | 可配置插件、凭据与全局键位，在独立测试环境开发和可选重载 | P2、P3 | 可复用已验证的配置和 UI 基础；与 P4 可独立推进，最终需集成 |
| P6 更新、清理及管理闭环 | 本地 JSON 目录可查更新，手动切换、失败回退、卸载和清理有明确结果 | P1–P5 | 更新必须覆盖工具、草稿、配置与凭据的真实在途状态 |
| P7 整体验收 | 在目标负载和故障下证明启动、交互、恢复、兼容及平台边界 | P1–P6 | 需要完整功能同时存在的测量，不能累加局部通过结果代替 |

P4 与 P5 的依赖只表示具备独立推进条件，不要求开并行代理或分支。各阶段内部先增加兼容入口、接入当前调用方，再移除确已无用的旧实现；不为了文件层次机械拆分任务。

P0 是一次性验证范围，不是缩小首版范围。其样例只画文字、矩形也可以开始验证，但 P3 的完整绘图对照表必须通过，才能交付初版 UI SDK。

## 2. P0：验证关键路径

产物已保存在 `codex/plugin-p0` 工作区。[最小测试插件和复现入口](../experiments/plugin-probe/README.md) · [接口与首轮实测](research/2026-11-12-plugin-p0-results.md) · [GPUI 能力清单](research/2026-11-12-plugin-p0-gpui.md)。

- [x] **P0-01 核心与插件分别就绪。** 空插件基线与本机示例插件都记录进程创建、基本操作、正文可编辑、插件输入/画面/业务就绪；无任何输入时插件仍开始准备。验证：Release 时间戳加真实输入响应检查。
- [x] **P0-02 真正跨进程。** 示例的条件判断、业务运行与宿主编辑分别处于既定进程边界；结束示例 runtime，正文仍可输入和保存。验证：真实进程故障注入。
- [x] **P0-03 计算与等待可控。** JS、WASM 忙循环及控制性慢读取有明确中断结果，正文和另一任务继续。验证：记录超时、实际结束与并行画面，真实文件系统阻塞取消留待平台验证。
- [x] **P0-04 文字和光标链路成立。** SDK 请求宿主文字布局后显示可编辑文字，输入由宿主确认，中文和 Emoji 位置可核对。验证：真实 GPUI、前台微软拼音及场景回调。Windows 自绘和网格试用版均已复测。
- [x] **P0-05 输入可恢复。** 示例接受一段输入后退出，宿主在进程退出期间继续确认输入，重启取回完整草稿。验证：对比最新输入与恢复画面，注入并拒绝旧运行代次响应。
- [x] **P0-06 两项目能分开释放。** 两项目共享同一插件进程，关闭一个只释放其独占状态。最后所有者关闭后进程结束，闲置时不退出。验证：真实进程、Store 数及待结束任务。
- [x] **P0-07 定义能力边界。** 固定 GPUI 版本列出公开绘图、准备、资源及平台专属入口，每项有映射和证据状态。验证：源码清单与样例对应关系。
- [x] **P0-08 形成选型依据。** 记录引擎、实验 ABI、消息表示、测试入口及替代方案。验证：E01/E02/E08 的实验定义和 P0-01–07 证据。

## 3. P1：安装与运行基础

产物：本地 ZIP 安装到最小 Installed/详情入口的真实流程、安装索引、兼容检查、受控缓存与 runtime 管理。普通用户安装不需要开发编译器。

- [x] **P1-01 身份规则。** 规格全部合法/非法 ID 示例、结尾换行、同 ID 不同名称、同名称不同 ID、本地化名称变化均符合 C02。验证：安装测试经过 ZIP 清单、安装索引及重装流程。
- [x] **P1-02 安装原子边界。** 好包能安装，坏清单、越界解包路径、损坏内容、中途退出及重复安装不会损坏上一安装或用户源 ZIP。验证：临时安装目录中的失败注入与恢复核对。
- [x] **P1-03 兼容原因准确。** 旧宿主/新能力、较旧宿主范围、平台缺失、未许可实验接口和实验契约不匹配分别拒绝并给真实原因。验证：构造包矩阵，证明拒绝发生在执行插件/迁移之前。
- [x] **P1-04 静态展示无需启动。** 查看名称、模块、普通设置声明或帮助只读取安装信息，不启动所有插件；冷缓存准备在核心就绪后执行，不加载包内冒充可信产物的原生缓存。验证：进程及任务轨迹，含损坏/丢失/伪造缓存。
- [x] **P1-05 运行与调用方绑定。** 每个活跃插件一个进程，调用者不能伪造名称/ID/句柄访问另一插件或开发环境数据；资源句柄代次失效正确。验证：作用域拒绝测试和两个真实进程。
- [x] **P1-06 安装权限一次确认。** 首次安装集中授权、拒绝有明确结果，未获能力不能绕过 SDK 调用，日常同权限使用不重复询问。验证：授权状态与调用结果；实验许可独立检查。
- [x] **P1-07 故障恢复有限。** 普通插件崩溃按 5 分钟最多 3 次、1/3/10 s 恢复；第三次成功不主动停用，耗尽后不因切焦点自动恢复。验证：可控时钟用例加真实退出测试；普通请求错误不重启整个进程。

## 4. P2：规则与项目生命周期

产物：真实 Modules/Activation rules 页面、异步数据接口、依赖追踪、配置提交和项目资源生命周期。

- [x] **P2-01 主动数据查询。** JS 动态选择宿主 API，文件返回磁盘内容、文档返回未保存内容；缺失、拒绝、错误和 false 区分。验证：修改内存正文与磁盘为不同内容并核对结果。
- [x] **P2-02 自动重算与失效。** 文件创建/删除、目录变化、动态分支、未保存正文和配置修订只重算受影响规则；发布前数据又变则旧结果不发布。验证：连续事件序列和遗漏通知后的重新核对。
- [x] **P2-03 并行和有界积压。** 同规则/作用域仅 1 个运行与 1 个最新待判断，不同规则能并行，当前交互优先而其他项目不饿死。验证：阻塞查询、持续变化和调度轨迹。
- [x] **P2-04 预算与重试。** 20 ms JS 累计预算、5 s 总预算、100/300 ms 两次临时读取重试正确，时间不随重试重置。验证：可控时间和真实 CPU 中断；明确测量误差与最大中断延迟。
- [x] **P2-05 故障范围准确。** 连续 3 次计算超限仅暂停对应规则/作用域/配置；普通数据变化不清零，成功清零，普通错误与 I/O 超时不误计。规则进程崩溃单独恢复，已有仍有效结果可用。验证：分支序列及两个项目对照。
- [x] **P2-06 大文件和未知格式。** 超过 10 MB 的文件可查询匹配部分/分段读取，完成与不完整结果可区分；未知语法可用随包轻量 JS 解析。验证：可复现大文件、无匹配、跨块编码、解析失败和预算耗尽夹具，不生成无界返回值。
- [x] **P2-07 规则不主动联网。** 直接和经宿主查询均不能发起网络请求，宿主已有状态读取无隐藏远端刷新；允许的文件路径不被偷偷缩小。验证：能力表及被记录的网络/宿主调用；网络盘等待按 I/O 预算处理。
- [x] **P2-08 Apply 与冲突。** 编辑规则/设置不立即生效，语法或保存失败保留旧目标；项目覆盖全局，false/0/空值有效，外部变化与草稿都保留。验证：真实配置文件加存储失败、并发外部写入及冲突选择。
- [x] **P2-09 重开边界。** 首次读取现有 `.nb/`；重开恢复最后已提交目标、未应用修改和失败信息，规则数据变动自动判断；配置候选不因重开自动生效。验证：关闭/重开与进程中断用例，尤其已提交但运行失败的新配置。
- [x] **P2-10 释放不靠闲置。** false、隐藏和长时间无调用保留打开项目实例；项目关闭完成收尾后独占任务/监听/UI/工具资源释放，其他项目继续。验证：重复开关项目达到有界对象数量，取消请求未完成时不提前释放。

## 5. P3：完整 UI SDK 与输入恢复

产物：首版绘图与交互 SDK、完整能力对照、主题/语言支持、普通输入及草稿恢复。

- [ ] **P3-01 全部目标绘图能力。** P0 建立的每一项公开能力有原生 GPUI 与 SDK 同场景对照，覆盖裁剪、顺序、字体、图片/帧、路径与状态组合；平台专属逐平台标注。验证：对照图、资源结果及差异解释，不能以几个基础图元通过替代全表。
- [x] **P3-02 网格与自绘可用。** 一个自绘样例和一个复用编辑网格样例都可交互；底部按单窗口覆盖切换，隐藏不卸载。验证：独立插件示例，不复制宿主内部私有对象给插件，不引入 Git 界面设计。
- [x] **P3-03 自动光标效果。** 标准输入及自绘语义文本均自动接入当前全部光标效果，滚动、裁剪、缩放、换字体后命中和光标一致。验证：真实交互矩阵及文字布局版本记录，静态标签不误变输入框。
- [ ] **P3-04 中文输入法。** 插入/搜索/路径输入可选词上屏；回列表/普通模式取消预编辑，之后第一个单键命令正确。验证：Windows 中文 IME 人工操作及原生路由测试，其他支持平台分别记录。
- [x] **P3-05 不丢已确认输入。** 输入过程中注入业务忙循环、UI 模块故障和进程退出，正文与业务输入保留；恢复期间不执行旧画面动作。验证：确认点前后故障序列，含粘贴、组合输入与未保存正文。
- [x] **P3-06 草稿保存与关闭。** 持续输入也保存，进程异常退出的最近输入损失目标不超过 1 s；写失败保留内存并提供关闭处理，秘密不进入草稿。验证：记录成功持久化修订、异常终止时间和恢复文本；磁盘失败分别测试，不能以定时器间隔代替结果。
- [x] **P3-07 正确替换画面。** 完整帧积压取最新有效帧，增量断链先重同步，尺寸/资源/运行代次改变后拒绝旧帧；超预算整幅拒绝并可恢复。验证：消息乱序、缺帧、重排、超复杂路径和大图资源，确认输入仍响应。
- [x] **P3-08 外观和翻译。** 主题、字号、DPI/用户缩放、语言变化只刷新相关界面，缺译文逐条回英文；不重启或额外启用模块。验证：普通控件及自绘各一组，用户文件和原始日志不被翻译。
- [x] **P3-09 字符按钮。** 各支持语言的助记字母下划线、唯一性与大小写匹配正确，点击与键盘同动作；搜索 Enter/Esc 标签按既定样式。验证：中英文及混合翻译回退场景，遵守当前项目约定。
- [ ] **P3-10 宿主资源回收。** 反复开关插件界面与项目，宿主字体/图片/布局/绘制引用有界；当前呈现仍在使用的资源不提前释放。验证：资源计数、失效句柄拒绝及持续运行趋势，不只看插件进程退出。

## 6. P4：编辑与工具能力

产物：版本化文档 API、多提供者结果、格式化、跨文件文本修改、结构变更预览、公共解析和受管原生工具。

- [x] **P4-01 文档协议。** 中文/Emoji/组合字符/CRLF/Tab 的位置与范围正确，关闭同路径后重开拒绝旧结果，增量丢失触发重同步。验证：真实 Document 行为和跨进程数据往返。
- [x] **P4-02 多提供者。** 快结果先显示、诊断按来源更新，慢/失败提供者不拖住其他结果，过期结果不回写；不启用所有已安装插件。验证：三个提供者的延时/重复/错误结果。
- [x] **P4-03 公共解析。** 同文档版本/grammar/配置可复用基础解析，嵌入语言范围更新正确；解析进程故障时正文可编辑保存。验证：可观察的复用数据、语法变更和真实进程退出。
- [x] **P4-04 格式化结果。** 完整编辑组一次应用一次撤销；选区与整篇区分，版本过期/取消拒绝整组，不自动重算、换插件或追加代码修复。验证：标准提供者夹具和撤销行为。
- [x] **P4-05 格式化计时。** 保存默认关闭；开启后总 1 s、手动 10 s 可取消，相同任务复用不重置，保存加入后取更早截止。验证：含排队/校验延迟的可控时钟与实际保存正文版本，保存未开启时不误取消手动任务。
- [x] **P4-06 默认选择。** 项目默认覆盖全局且只指定身份；多候选首次手动选择，启动不弹窗、保存不等选择，失败仅提醒。验证：零/一/多候选及默认插件不可用场景。
- [x] **P4-07 跨文件文本修改。** 完整计划可预览，全部目标检查，过期计划不覆盖新输入，成功后整组撤销；未保存文件参与。验证：多文档、并发编辑、磁盘保存失败与撤销冲突，说明文本/写盘分别结果。
- [x] **P4-08 文件结构操作。** 创建/删除/移动/重命名清单含覆盖信息，同一清单只确认一次；中途失败停止并区分结果，不能覆盖新内容或整批重放。验证：临时项目夹具中的权限、碰撞、脏文档、部分成功及回复丢失。
- [x] **P4-09 工具准备与执行许可。** 受管下载/解包或已有路径均可用，项目首次代码执行选择本机保存；拒绝仅影响相关功能，不改 PATH、不删用户工具、不主动提权。验证：无副作用测试工具及临时项目，不接入真实部署/凭据。
- [x] **P4-10 工具恢复与可选协作。** 安全后台服务独立恢复并同步未保存正文，一次性任务不重做；合作插件缺失只影响附加功能，不安装依赖。验证：真实工具退出、旧会话响应、可选伙伴缺失/禁用/超时。

## 7. P5：设置与开发工具

产物：静态普通设置、自定义设置入口、配置迁移、全局快捷键、专用凭据及独立 SDK 开发环境。

- [x] **P5-01 设置不依赖插件存活。** 普通设置由声明生成，插件未启用或故障时也可配置；复杂设置经同一配置服务提交。验证：相同数据通过两种 UI 保存，未启用插件不被设置操作拉起。
- [x] **P5-02 作用域和 Apply。** 项目共享/仅本机逐项区分，允许声明本机项目覆盖；失败保留旧目标与草稿，运行拒绝新值则保留新值及错误。验证：继承、取消覆盖、失败重试和恢复旧值到草稿后 Apply。
- [x] **P5-03 升级设置转换。** 等价转换保留原文，写配置仍需 Apply，未知/删除/改义项保留提示；不扫描改写其他项目、不冻结继承默认值。验证：各层显式值/缺省值和转换失败夹具。
- [x] **P5-04 全局改键。** 个人映射所有项目共用且不写 `.nb/`，冲突不被新默认键覆盖，帮助同步真实映射；上下文/IME/模块条件仍正确。验证：两个项目、不同模式、键盘与帮助对照，配置环境相互隔离。
- [ ] **P5-05 凭据隔离与失败。** 名称＋ID＋配置环境隔离，锁定/缺失/拒绝明确，不降级明文、不阻塞启动。验证：测试存储适配器失败注入和各平台专用测试条目，检查配置、日志、草稿、导出无秘密正文。
- [x] **P5-06 秘密 Apply。** 未提交秘密仅会话内存，离开可处理；新秘密写入或配置引用发布中断保留一致旧组合，可恢复核对；提交后认证失败不偷用旧值。验证：逐保存边界注入故障，不读取用户真实凭据。
- [x] **P5-07 独立开发环境。** 本机构建加载与重载不影响日常安装、配置、草稿和异常计数，实验接口仍需显式许可；真实项目副作用有准确说明。验证：两个环境用相同插件身份、不同测试数据对照。
- [x] **P5-08 可选自动编译。** 逐插件开关仅本机、仅主动开发会话生效，失败保留版本，只采用最新完整构建；重载等写操作、不自动 Apply 或刷新市场。验证：连续保存、失败构建、关闭开关/会话及旧结果迟到。初始关闭仍标 E07 建议。

## 8. P6：更新、清理及管理闭环

产物：完整管理面板、本地 JSON 市场适配、手动更新与回退、卸载/清理、缓存及运行诊断。

- [x] **P6-01 完整键盘流程。** `Space`→`Shift+P` 打开插件弹层，`/` 将底部快捷键提示切换为筛选输入。`Enter` 应用筛选，`Esc` 恢复筛选前的查询和选中项。三页签支持数字键和点击，`?` 打开帮助。在列表中按 `Enter` 打开详情，按 `q` 或 `Esc` 返回。
- [x] **P6-02 模块状态真实。** Ready/Preparing/Not matched/Rule error 等按实际作用域展示；false 不等于已卸载，原因未知不猜测；查看不额外执行规则。验证：状态组合夹具与真实规则切换。
- [x] **P6-03 市场只在两个时机读取。** 本地 JSON 中的真实 ZIP 可安装；只在核心启动后和 Marketplace 打开检查更新，坏数据/离线不阻塞已装插件；无定时器、额外刷新入口或 JSON 监听。验证：记录目录适配器调用序列。
- [x] **P6-04 手动更新与兼容。** 发现新版本只提示，用户 Update 后后台准备，选择兼容包；新增权限需确认，拒绝保留原版本；高要求包不会替换现有包，旧宿主显示升级原因。验证：多包版本/宿主范围/权限矩阵及真实更新。
- [x] **P6-05 在途操作与回退。** 写操作未收尾不切换，可 Later；接管前启动/迁移失败恢复兼容旧包及状态，最新宿主草稿保留。验证：各切换边界失败注入，确认不存在并行接管用户操作的两个 runtime。
- [x] **P6-06 不重复外部操作。** 操作完成但回复丢失后查询实际结果，未知就显示待确认；更新/重启/卸载不重放，接管后不拿旧快照覆盖新数据。验证：可记录副作用次数的无害工具，而非真实 Git 提交或部署。
- [x] **P6-07 卸载与清理。** 卸载可取消等待，默认保留设置/规则/草稿/凭据；清理仅选中范围，凭据默认不选，只有凭据也能从 Retained data 进入。验证：离线清理、删除失败、同身份重装、变身份不继承、用户工具/ZIP/`.nb/` 不受影响。
- [x] **P6-08 有界缓存与文件刷新。** 大量磁盘事件合并且持续推进，不能丢正文/操作记录或自动 Apply；缓存只清未占用可重建项，旧项目重开可重建。验证：持续事件流、目录变化、共享引用、容量触发和清理中断。
- [x] **P6-09 诊断与内存保护。** Overview 轻量概况、Logs 有界、详细采样按需；超限先限分配/清缓存，再停止最小范围并暂停自动恢复，其他项目继续。验证：真实压力、宿主间接占用归因及秘密日志检查。

## 10. 性能测量口径

### 必须区分的条件

| 维度 | 最低记录内容 |
| --- | --- |
| 机器 | CPU、内存、GPU、系统版本、显示缩放/刷新率、存储及电源模式 |
| 程序 | 精确构建/提交、Release 产物、依赖及运行时版本、编译配置 |
| 项目 | 固定项目夹具、文件规模、初始打开文档/启动页、规则与插件包清单 |
| 系统缓存 | 已热；经可说明方法得到的真冷；仅关闭再开不能标真冷 |
| 编译缓存 | 命中、缺失、失效分别记录；系统缓存冷热不代替编译缓存状态 |
| 计时 | 外部启动点/进程创建、首帧、基本操作、指定正文可编辑、插件各就绪点 |
| 样本 | 次数、完整原始值、P50/P95/P99、失败/超时/异常；不随意丢异常样本 |
| 输入 | 事件到正文提交、场景提交与真实屏幕呈现分别标注；CPU 绘制耗时不是输入到屏幕耗时 |
| 资源 | 宿主、runtime、JS/解析进程、工具及宿主间接资源；私有提交、工作集、共享映射分别解释 |

### 最低场景矩阵

| 场景 | 主要目的 |
| --- | --- |
| 0 个插件 | 当前核心编辑器基线，先辨别核心自身是否已经超目标 |
| 50 个安装、无业务模块条件匹配 | 衡量静态索引与规则成本；不能靠完全跳过规则伪造 |
| 50 个安装、典型 10 个活跃 | 主验收负载，明确每个活跃插件执行哪些工作 |
| 同上，系统冷/热 × 编译缓存命中/缺失 | 分清文件缓存与编译准备；缓存失效额外一组 |
| 只阅读、启动页、空正文项目 | 证明插件准备不等首个编辑动作，计时对象按场景说明 |
| 两项目、持续输入和后台索引/解析 | 衡量公平调度、交互与工具负载 |
| 大文件匹配、持续文件事件、消息/图形压力 | 衡量有界工作与合并；不能把不完整查询当正常无结果 |
| 无限循环、阻塞 I/O、进程退出、内存超限 | 衡量中断/恢复隔离及输入保护 |
| 更新/Apply/存储各边界故障 | 验证确认、持久化、回退和副作用核对 |

样本规模属于工程方法，不新增产品承诺。建议正式热启动每组至少 100 次、真冷每组争取 100 次；条件有限时如实记录数量与不确定性，小样本不能宣布 P95 已证实，更不能凭几个样本解释 P99。先用较小试跑发现问题，再执行一次完整验收，避免无依据地反复扩大测试。

除已确认的启动、草稿、规则和格式化数值外，输入尾延迟、绘制限额、内存/磁盘额度、并发与事件窗口没有用户确定的数字。P0 测基线并提出初值，P7 根据报告固定可调整默认值；报告必须展示相对基线的变化和仍有的长停顿，不能仅写“流畅”。
