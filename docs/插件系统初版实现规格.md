# 插件系统初版实现规格

整理日期：2026-11-12。适用项目：Nanobug V2。

**状态：已确认需求的实施基线，P0 已完成关键路径初测。** 本文集中记录截至 Q106 的最终行为约定。首版功能和目标负载验收按后续阶段实施。

配套：[分阶段验收清单](插件系统分阶段验收.md) · [P0 验证报告](research/2026-11-12-plugin-p0-results.md) · [原始决策及研究依据](research/2026-11-08-plugin-architecture.md)。后续从 P1 的本地 ZIP 安装与正式兼容检查接续。

## 1. 问题说明

用户希望插件能提供语言功能、自己的界面和外部工具，同时保持编辑器快速启动。一个插件变慢、出错或退出时，正文仍应能操作；用户已经输入的内容不能因为插件重启而丢失。

当前编辑器已有正文模型、字符网格、光标动画和输入法路由。P0 实验复用了这些能力来验证独立规则与插件进程。完整插件加载器、公开 UI SDK、规则服务及恢复协议按本规格推进。

## 2. 解决方案与阅读约定

核心编辑器先准备好基本操作，再自动判断插件条件并准备符合条件的模块。宿主管正文、输入、权限、资源及真实绘制；插件管理自己的功能逻辑与区域内界面。插件故障只恢复受到影响的部分，恢复时以宿主保存的有效状态为准。

本文使用三个状态：

| 标记 | 含义 |
| --- | --- |
| 已确认要求 | 用户已经决定的行为，实施不得自行改成相反方案 |
| 工程约束 | 为落实上述行为必须满足的一致性、所有权或失败处理要求 |
| 工程建议 E01–E08 | 本次整理提供的具体落地办法；可通过原型和测量调整，不能记成用户逐项采纳 |

后面的 C01–C18 是实施契约编号，P0–P7 是验收阶段编号。阶段完成只说明该阶段通过，全部首版范围通过后才能宣布初版完成。发生文字冲突时，以用户较晚的明确决定为准，并同步修正规格；不能用旧提案覆盖新决定。

## 3. 用户故事

1. 作为编辑器用户，我希望安装很多插件后仍能迅速开始编辑，以免插件准备拖住启动。
2. 作为只打开项目阅读的用户，我希望符合条件的插件自动准备，以免必须先输入或执行命令。
3. 作为多项目用户，我希望关闭 Vue 项目后释放它独占的资源，同时保持 Rust 项目工作。
4. 作为用户，我希望打开的项目保留已经加载的模块，以免短暂闲置后反复初始化。
5. 作为用户，我希望单个插件卡死或退出时正文继续响应，并能找回插件界面中已经确认的输入。
6. 作为用户，我希望编辑器意外退出后恢复已保存的业务草稿，并明确知道保存失败。
7. 作为用户，我希望提交、部署等操作在恢复时不会被重复执行，并能看到结果是否需要核对。
8. 作为用户，我希望用键盘进入插件列表、搜索、详情、模块状态和日志，以便快速管理插件。
9. 作为用户，我希望规则修改先保存为草稿，按 Apply 后再生效，以免编辑一半就改变运行状态。
10. 作为用户，我希望项目设置能覆盖全局设置，并保留外部修改与本地草稿的双方内容。
11. 作为用户，我希望重新打开项目后继续采用最后提交的配置，同时保留待应用内容和错误信息。
12. 作为用户，我希望项目只指定使用哪个插件，不需要为项目维护插件版本。
13. 作为用户，我希望从官方目录或本地 ZIP 安装兼容的插件；编辑器太旧时能得到明确升级提示。
14. 作为用户，我希望自己决定何时更新，并在更新失败时继续使用上一有效版本。
15. 作为用户，我希望更新、卸载和开发重载等待正在写文件的操作收尾，并保留草稿。
16. 作为用户，我希望卸载后保留设置、草稿和登录信息，需要时再主动清理。
17. 作为用户，我希望安装时一次看清权限，普通使用不反复询问，新增权限和项目代码执行另有明确边界。
18. 作为用户，我希望外部工具由编辑器管理，也能使用自己已经安装的工具。
19. 作为用户，我希望多个语言功能能一起提供有效结果，而一个慢插件不拖住其他插件。
20. 作为用户，我希望跨文件修改有完整计划、预览和整组撤销，旧结果不会覆盖新输入。
21. 作为用户，我希望格式化失败只停止该次格式化并提醒，保存仍能继续。
22. 作为用户，我希望插件常规设置、复杂设置、快捷键和登录信息有一致且明确的保存方式。
23. 作为用户，我希望个人快捷键在所有项目中一致，帮助窗口显示实际有效的按键。
24. 作为用户，我希望插件界面跟随语言、主题和缩放，并正确使用中文输入法。
25. 作为插件作者，我希望首版就有 UI SDK，也能自己绘制界面并借用编辑区网格。
26. 作为插件作者，我希望 SDK 覆盖当前 GPUI canvas 的公开绘图能力，并说明平台差异。
27. 作为插件作者，我希望通过 SDK 提交文字和交互语义后自动接入全局光标效果，无需再写效果适配。
28. 作为插件作者，我希望条件脚本能按需读取宿主数据、使用随包提供的轻量解析代码，并自动响应数据变化。
29. 作为插件作者，我希望稳定接口保持兼容，实验接口明确标识，旧宿主不会误运行不兼容产物。
30. 作为插件作者，我希望在独立测试编辑器中加载本机构建产物，可选择自动编译与重载。
31. 作为插件作者，我希望插件之间可以协作，但核心功能不强制依赖另一个插件。
32. 作为维护者，我希望看到启动、准备、运行、绘制、资源和恢复的实际数据，以便判断性能问题。

## 4. 实施契约

### C01 启动与就绪

**已确认要求：**设计负载为 50 个已安装插件、典型工作区最多 10 个同时活跃；这是初始测量规模，不是产品数量上限。在这台电脑的 Release 版上，启动到可编辑的 P95 初始目标为系统缓存已热时不超过 300 ms、真正冷启动不超过 1 s。插件首次可用时间单独记录。

- 核心界面及当前场景的基本操作就绪后，自动开始规则和模块准备。无输入、只读浏览、启动页或暂时没有打开正文，也不能无限等待首个操作才开始。
- 条件满足即进入加载和调用调度，不再增加“第一次实际使用才激活”的门槛。排队不等于条件不满足。
- 启动关键路径只读取必要的小型安装索引及配置记录；不运行所有插件、不遍历所有 WASM、不等待市场、凭据库、解析服务或外部工具。
- 安装和更新时提前准备清单索引与可复用编译缓存。缓存缺失、损坏或不兼容时在核心就绪后重建，不能把缓存存在当作正确性前提。
- 本机编译缓存按包内容、引擎版本/配置和平台识别，由受控编译链生成；不将插件随包提供的任意原生缓存直接当可信代码加载。
- 首帧、基本操作可用、指定文档可编辑、插件输入可用、首个有效画面及首个业务结果分别计时。出现空窗口不等于可编辑。
- 所有数值是验收目标；具体采样方法见验收清单，不能用 Debug 构建或少量热启动证明达标。

### C02 插件身份与包清单

**已确认要求：**清单中的规范名称和 ID 同时相等，才按同一插件处理更新、重装和原有数据保留。比较规范名称原值，不比较本地化显示名。

| 项目 | 契约 |
| --- | --- |
| ID | 必填、非空，只含 ASCII 小写字母、数字和 `-`；首尾不得为 `-`；数字可以没有 |
| 合法示例 | `git`、`rust-tools`、`vue3-helper`、`a`、`123`、`3d-view`、`a--b` |
| 非法示例 | 空字符串、`-git`、`git-`、`Git`、`rust_tools`、带空格或换行的字符串 |
| 不附加的限制 | 不要求字母开头、必须含数字、禁止连续 `-`、最少两个字符或 ID 单独全局唯一 |
| 名称或 ID 改变 | 视为不同身份，不自动继承旧设置、规则、草稿和凭据 |
| 同名同 ID | 仍需正常的主动安装/更新、兼容性、权限与包有效性检查；不代表来源真实性已经核验 |
| 数据命名空间 | 完整身份组合加配置环境；不能只按 ID 保存，也不能把未经编码的名称直接当磁盘路径 |
| 运行调用方 | 宿主从安装记录和通信会话绑定；请求不能自报另一身份访问其他插件数据 |

清单至少能表达下列信息。**具体字段名、文件格式及序列化属于 E01 工程建议，不是已冻结 ABI。**

| 信息组 | 必需表达的含义 |
| --- | --- |
| 身份与版本 | 规范名称、ID、插件包版本、显示文案、兼容宿主范围 |
| 模块 | 模块标识、职责、作用域、入口或资源、默认 JS 规则；静态数据可以不含可执行 WASM |
| 能力需求 | 必需/可选宿主能力、平台范围、权限、所选实验提案及契约记录 |
| 静态贡献 | 命令、建议快捷键、普通设置、语言资源、详情文案及模块补全信息 |
| 可选资产 | grammar、查询、字体/图像、轻量规则解析代码、受管外部工具声明 |
| 构建检查记录 | 实际导入、SDK 与目标基线、完整性信息；宿主可复核，不能只信任作者自报 |

不设置必需的其他插件依赖字段，不支持项目指定插件版本。包内路径、解包边界、重复身份及中断安装必须在执行插件前检查；坏包不能破坏已有安装。来源仍记录，但不恢复已被否决的额外作者同源门槛。

### C03 API 版本与实验能力

**已确认要求：采用后来确认的 VS Code 方式，替代固定兼容前两个主版本的淘汰窗口。**

- 插件包版本、所需编辑器版本范围、SDK 版本和公开 API 标记分别管理。当前公开 API 标记固定为 `1.0`，只手动更改；相同 `1.0` 不是兼容证明。
- 稳定接口长期向后兼容，验证旧插件的原始 WASM 产物，而不仅是重新编译后的源码。稳定接口确需破坏性迁移时，提供可用迁移路径和三个月提前通知；到期不自动删除。
- 实验能力独立命名、显式声明并通过开发/测试路径启用，允许不兼容演进，不套用稳定接口的三个月承诺。仅标为 preview 不能获得实验权限。
- 初版优先验证并稳定注册、生命周期、文档、草稿及资源释放等基础接口。UI SDK 与自绘接口先实验交付，**实验标记不减少首版绘图范围**。
- 宿主在执行前核对宿主范围、实际导入、必需平台能力及实验契约。基础版本满足但实验契约不匹配时，报告实验接口不匹配，不能误报宿主太旧。
- 旧宿主低于必要要求时明确显示“编辑器版本过低，请升级”，保留原有可用包；不自动升级编辑器。
- 实验契约记录由 SDK/构建工具生成，覆盖接口及行为修订；无关宿主改动不能使全部插件失效。稳定接口不要求与最新整套 SDK 哈希相等。
- 可选能力必须有真实可用的降级路径，不能把无法解析的强制 WASM 导入写成“运行时再判断”。

源码 SDK、WASM 调用契约、宿主与 runtime 的内部通信、业务状态格式是不同层次。内部引擎升级和通信调整不得无声改变稳定公共行为。实际范围表达式、实验标识生成及接口表示在 E01/E02 中落地。

### C04 进程职责与通信

| 对象 | 职责及隔离边界 |
| --- | --- |
| 编辑器宿主 | 正文真源、输入与草稿、配置提交、资源与权限、调度、GPUI 绘制、操作确认 |
| 每个活跃插件的 runtime | 一个插件一个进程，容纳其选中的业务/UI 模块；重任务与 UI 分开调度 |
| 公共 JS 规则进程 | 仅执行启用判断；独立于宿主和插件进程，有逐规则预算及恢复计数 |
| 公共语法解析进程 | 复用基础解析，与 JS 进程分离；故障可影响多个语法功能，但不阻塞正文编辑保存 |
| 受管原生工具 | 宿主统一准备、启停、归属和统计；按工具能力决定共享安装文件或运行实例 |

安装单位、进程隔离单位、按条件选择的模块、资源和项目实例不是同一对象。一个插件供多个项目使用，不因此为每个项目再启动完整插件进程；需要独立释放的项目状态必须能独立结束。

**工程约束：**

- 消息与任务队列有界；文本输入、编辑提交、有副作用命令必须有顺序和明确结果。繁忙时可明确拒绝，不能静默丢弃。
- 完整快照/完整画面可用最新有效版本替换过时排队项；增量不能任意丢中间项，断链后重同步。
- 关闭、取消和健康检查须保留处理能力。收到取消请求不等于底层 I/O 已结束，也不等于资源已可释放。
- 宿主输入和绘制回调不等待插件同步响应；不能为每个字形、原语或键盘事件做同步往返。
- 识别无响应要覆盖实际工作通道，不能只凭独立心跳仍在就判断插件健康。
- 所有迟到结果先验证所属安装、作用域、运行代次及内容版本；无效结果不得触碰正文、资源或新实例。

**E01 建议的公共消息信息**：请求标识、运行代次、作用域句柄及打开代次、有效配置修订、所读数据版本、操作类别、取消标记/截止时间、完整结果或明确错误。按操作需要携带相应字段；具体名称和字节编码不冻结。调用方身份由通道绑定，不由这些字段授权。

### C05 模块与资源生命周期

**已确认要求：项目关闭时释放独占资源；项目仍打开时不因闲置回收。**

| 事件 | 新调用 | 实例与资源 |
| --- | --- | --- |
| 已安装但条件未匹配 | 不放行该上下文的模块调用 | 只有静态注册及磁盘产物；不为所有模块创建实例 |
| 条件首次为 true | 进入准备调度，准备成功后服务 | 创建或复用所属插件进程及对应作用域实例 |
| 面板隐藏、切走焦点、长时间没调用 | 仍按规则及权限判断 | 不按闲置时长销毁实例，不把面板隐藏等同项目关闭 |
| 条件变 false，项目仍打开 | 停止该上下文的新调用 | 保留已有实例与必要状态；暂停/取消可安全停止的后台工作，副作用操作核对收尾 |
| 条件未知或执行失败 | 只有仍有效的成功结果可继续放行 | 保留实例和草稿，不把错误当成 false 或项目关闭 |
| 关闭文档/项目 | 封闭相应作用域，拒绝旧结果回写 | 先处理输入和在途操作，再释放独占实例、任务、订阅、宿主 UI/资源及工具引用 |
| 最后一个资源所有者结束 | 无新业务调用 | 完成必要收尾后退出 runtime 和独占工具；磁盘保留项按各自规则处理 |
| 显式禁用、卸载、故障重建 | 按明确状态阻止或恢复 | 清理旧代次资源，保护已确认输入和结果核对记录，不按闲置逻辑处理 |

资源所有者包括仍打开且保留实例的项目、有效窗口/全局功能，以及尚未收尾的操作，不是“最近调用过的人”。其他项目仍需共享资源时只撤销当前项目引用。

宿主文字布局、图像/GPU 资源不会随插件进程退出自动消失，必须按归属清理并等当前绘制使用结束。已完成任务释放临时缓冲，可重建缓存按预算淘汰，这两件事不等于闲置卸载插件。

关闭 Vue 项目而保留 Rust 项目时，Vue 独占状态与工具结束；若 Vue 插件再无使用方则进程退出。若另一项目仍用同一插件，仅释放关闭项目的部分。验收看存活对象、进程及有界资源趋势，不承诺任务管理器每次立刻下降某个精确字节数。

### C06 JS 规则与数据查询

**已确认要求：JS 按需调用宿主数据 API，使用返回的数据为对应模块给出 true/false；宿主决定如何执行。** 不恢复“只能读取预先填好的固定上下文”的限制。

| 接口类别 | 行为 |
| --- | --- |
| 文件数据 | 读取已经保存的磁盘数据；存在、缺失、无权限、读取失败分别表达 |
| 文档数据 | 读取包含未保存修改的当前正文；文档身份、打开代次与内容版本明确 |
| 项目及宿主状态 | 读取已获准的项目信息和宿主已有状态，不暗中刷新远端数据 |
| 等待型 API | 使用异步调用；等待期间不占用规则的 JS 执行线程，宿主不阻塞 UI |
| 解析 | 常见格式可由宿主提供便利接口；未知文本格式可由随插件交付的轻量 JS 解析代码处理 |
| 大文件 | 不按源文件总大小设置读取上限；允许范围/匹配查询、分批返回和完整扫描，实际工作仍受资源与时间预算约束 |

不把任意文件当文本；二进制、文本解码、结构化解析、解析失败需要明确区分。未知格式不等于不能读取原始内容，也不等于宿主能理解所有语法。JS 解析代码受同一预算，不提供完整 Node.js 或任意 npm 环境的承诺。

初版条件 JS 不主动联网，不能经宿主查询接口绕过；没有任意命令执行或写文件能力。获授权的已启用业务插件可执行自己的联网功能。此限制不缩小已经允许的文件路径范围，也不承诺网络盘等底层文件读取绝无网络 I/O。

当前实现的项目外规则文件使用独立的 `read_rule_paths` 许可。安装确认显示清单中的确切文件名，确认前不探测这些路径；更新或开发重载复用原授权，新路径另行确认。规则不通过符号链接或目录联接跨越范围。具体字段及项目外文件更换后的处理见 [SDK 使用说明](../plugins/sdk/README.md)。

宿主记录实际读取形成的依赖，包括文件缺失、目录查询、文档版本和分支内读取。依赖变化后刷新缓存并只重算受影响规则；动态分支改变时更新依赖集合。不依赖作者另写监听代码。结果发布前再次验证配置与数据版本，不把旧结果套到新上下文。

| 规则事件 | 已确认处理 |
| --- | --- |
| 一次判断 | 累计 JS 计算初始预算 20 ms；从开始执行起含 I/O 的总预算 5 s；排队时间另记 |
| 临时读取失败 | 最多再试两次，分别等待 100 ms、300 ms，仍在原 5 s 内；权限/格式等明确错误不盲目重试 |
| 数据连续变化 | 同一规则、作用域保留 1 个运行判断和 1 个最新待判断；旧结果不发布 |
| 不同规则 | 限量并行，当前交互优先，其他项目持续推进 |
| 连续计算超限 | 同一规则、作用域及有效配置连续 3 次耗尽计算预算，暂停自动判断；普通数据变化不重置，修改规则或手动重试可恢复，成功后清零 |
| 普通错误/总等待超时 | 是失败，不是 false；不计入上述连续计算超限次数；只复用仍有效的成功结果 |
| 查询未扫完或结果被截断 | 明确返回不完整/继续读取信息，不把“未找到”当成完整扫描后不存在 |
| 规则进程崩溃 | 独立使用 5 分钟内最多 3 次、间隔 1/3/10 s 的恢复规则 |

**E03 工程建议：**先实现存在检查、文本/字节分段读取、文档快照及受限查询；结构化筛选的存在、相等、数字范围、文本匹配和逻辑组合清单仍是原 Q32 建议。具体操作、编码、缺失/null、类型比较、大小写及范围边界在该接口实现前形成明确契约与用例，不将候选清单冒充已采纳范围。

### C07 配置、规则与 Apply

**已确认要求：**规则和宿主管理的普通设置先成为草稿，按 Apply 才提交；项目共享配置在项目根目录 `.nb/`。规则页面提供 Current project 与 All projects，默认当前项目。

| 状态 | 含义 |
| --- | --- |
| 已提交目标 | 已完成必要保存、决定应采用的配置，不等于插件已经成功采用 |
| 当前运行状态 | 实际采用了哪些有效值、哪些模块已就绪或失败，单独报告 |
| 本地草稿 | 用户尚未 Apply 的修改，普通内容可持久保存 |
| 外部候选 | 文件被外部编辑器或 Git 修改后的待应用版本 |
| 冲突 | 草稿与外部版本均保留，可比较、选一方或手动合并，随后 Apply |

按模块/设置项使用“项目显式值 → 全局用户值 → 插件默认值”。false、0 和空值不能误当未设置；取消覆盖才恢复继承。只影响相关模块，不为修改未启用插件的设置而强行启动它。

Apply 依次检查草稿、冲突与约束，完成必要配置和已提交版本保存，再发布新修订。语法或保存失败保留旧目标与草稿。新修订运行失败则保留新目标并显示错误；用户可修正后 Apply、重试采用当前值，或把旧值恢复到草稿再 Apply，不能悄悄退回旧工具或目标。

首次打开且没有本机应用记录时，在核心就绪后读取并检查现有项目配置；重开时恢复最后已提交目标，保留待应用修改、冲突和运行失败信息，再结合当前全局值求有效配置。不能把“最后运行成功值”误当“最后提交值”，也不能因重开自动应用外部修改。

规则源文件改变走 Apply；规则读取的业务数据改变自动重算。这两条更新通路必须分开。缺少插件时列出项目引用并提供安装入口，不自动执行项目要求的安装。

工程实现必须保留提交记录与必要恢复信息，处理配置保存一半、进程退出及外部并发修改。**E04** 建议采用可校验的提交修订及写入中断恢复记录；具体文件组织和保存实现不在本次冻结。

### C08 输入、草稿、恢复与副作用

**已确认要求：**宿主仍活着时，插件故障不能丢失已经由宿主确认的正文修改和可恢复业务输入。SDK 标准输入自动接入；自定义交互绑定同一宿主状态接口。

| 数据 | 权威位置与恢复边界 |
| --- | --- |
| 编辑正文 | 宿主文档模型；插件仅拿版本化快照/增量并提出修改 |
| 普通可恢复业务输入 | 宿主先记录再显示为已接收；插件重启读取最新状态 |
| 跨编辑器重启的业务草稿 | 宿主后台合并持久保存；持续输入也推进保存，正常关闭前完成最后保存 |
| 密码、令牌 | 只走 C16 专用存储；未提交秘密不进入普通草稿恢复 |
| 索引、预览等可重建数据 | 可丢弃重建，不与用户输入混放 |
| 提交、部署、写文件等操作 | 保留足够的操作与结果信息；恢复时核对实际结果，未知则明确报告 |

存储正常时，编辑器进程异常退出的业务草稿损失初始目标不超过最近 1 s 输入。这个目标不等于“一秒定时器已经达标”，不覆盖系统掉电，也不自动建立正文自身跨宿主崩溃的恢复系统。

草稿保存失败时保留内存并继续编辑，明确未保存状态并有限重试。正常关闭受影响项目/编辑器前允许重试、另存/导出、取消关闭或明确放弃；成功或明确放弃后才释放。秘密不能借导出路径进入普通文件。

插件 runtime、公共规则进程、可独立恢复的外部服务各自计数：任意 5 分钟内最多自动重启 3 次，依次等待 1、3、10 s；第三次成功后继续运行，再次失败且无额度才暂停，提供手动重试。暂停后不靠切换焦点或时间窗口过去而自行重新尝试。

恢复递增运行代次，撤销旧句柄和旧响应，重新同步当前正文、未保存修改、有效配置及宿主输入；只恢复当前规则和权限仍放行的工作，不借恢复启动未被选择的模块。能独立安全重建的工具先单独恢复。普通请求错误不升级成整个进程重启；内存保护停止按 C18 暂停，不套普通自动重启循环。

外部操作完成但回复丢失时，先查询实际结果；无法确认就显示“结果待确认”。请求编号本身不提供恰好执行一次的保证；取消、超时、重启和回退都不能盲目重放或声称撤销外部副作用。

宿主连续启动崩溃时，下次由用户启动进入临时仅核心模式，保留安装、配置及草稿并提供主动恢复入口。触发次数及记录方式属于 E05，不擅自判断某插件有罪或永久卸载它。

### C09 文档、语言结果与编辑操作

插件文档访问必须区分文档身份、打开代次、正文修订及磁盘状态。关闭后以同一路径重开也不能接受旧代次结果。位置单位、Unicode 边界与换行表示由 E01 明确；SDK 和宿主必须一致转换，覆盖中文、Emoji、组合字符、Tab 和 CRLF。

- 补全/诊断可由多个适用且已启用的提供者产生，先显示有效结果，标明来源并合理去重；某个提供者慢或出错不拖住其他结果，旧版本不覆盖新结果。
- 单文档修改收齐完整修改组，核对全部范围和基准版本后一次应用、一次撤销；过期时整组拒绝，不部分应用。
- 跨文件文本修改是首版基础能力：完整计划、统一预览入口、所有目标版本检查、宿主应用及整组撤销。包含未保存文档；失效计划不覆盖新内容。文本应用与写盘结果分别报告，不承诺任意磁盘操作全部原子回滚。
- 经宿主批量创建、删除、移动或重命名项目文件，先显示完整清单和删除/覆盖范围，同一清单确认一次。预检并在执行中再核对路径、权限、碰撞及未保存正文；失败停止后续步骤，区分完成、失败、未执行和结果未知。
- 结构变更确认不套到普通读取、纯文本编辑、私有缓存或原生工具直接写盘；安装权限也不替代该次清单确认。不得覆盖执行期间出现的用户新修改或盲目重放整批。

格式化分支已经收敛，不再展开产品问答：

| 场景 | 行为 |
| --- | --- |
| 默认提供者 | 按功能/文件类型设置，项目覆盖全局，Apply 后生效；只记插件身份，不记版本 |
| 未配置默认 | 唯一合格提供者直接用；多个时首次手动使用再选，启动不弹窗，保存不等选择 |
| 提供者不可用/失败 | 仅终止该次格式化并提醒；不自动重试、换插件或给本次临时替代入口 |
| 保存时格式化 | 默认关闭；开启后额外等待初始上限 1 s，包含排队、准备、通信、校验；超时继续保存正文，磁盘写入时间另算 |
| 手动格式化 | 初始上限 10 s，可取消，等待时继续编辑；相同任务复用且不重置时钟 |
| 保存加入相同手动任务 | 共用任务，截止时间取原 10 s 截止与保存起 1 s 截止中更早者，结果只应用一次 |
| 保存与手动任务不同 | 已开启保存格式化时保存优先，旧结果失效，保存格式化仍受总 1 s 限制 |
| 保存格式化未开启 | 直接保存，不替仍有效的手动任务延时、取消或隐式自动保存其后续结果 |

取消、文档变化、关闭/重开后的迟到结果均拒绝；失败不影响原保存流程，实际保存哪个正文版本必须可知。整篇与选区分开，不隐式加入整理导入或代码修复，提示合并避免重复打扰。

### C10 UI SDK、绘图与区域

**已确认要求：首版提供 UI SDK，并完整覆盖当前锁定的 `gpui-pre 0.3.10` canvas 公开绘图能力，平台专属能力单独标明。** 这不是任意二维引擎全部能力、任意未来 GPUI API、3D 或任意 shader 的承诺。

插件可选宿主公共控件或自绘，允许借用编辑区域网格实现自己的内容与交互。Git 界面由用户另行设计；不把只读虚拟文档提案恢复为首版要求，不限制所有插件内容只能只读。底部当前默认一个窗口覆盖切换，其余区域布局暂缓。

| 覆盖类别 | 必须核对的内容 |
| --- | --- |
| 文字与基本图形 | 字形、Emoji、下划线/删除线、矩形/圆角/边框、路径/曲线，以及原生支持的填充、渐变与阴影 |
| 图像及资源 | SVG、图片与图片帧，字体/图像准备、引用与释放 |
| 绘制状态 | 原生支持的裁剪、偏移、透明度、原语变换、批次和顺序；不把 paint layer 扩称任意离屏纹理图层 |
| 准备与布局 | 区域尺寸、坐标、文字测量与资源准备结果，布局版本与显示画面一致 |
| 交互支持 | 命中、焦点、键鼠、文本输入、IME、帧请求和受管回调标识 |
| 平台专属绘制 | 列出相应平台资源桥接，例如 Apple 平台原生 surface；不把原生指针直接传给 WASM |

上表是类别，不是穷尽的函数清单。P0 核对固定版本源码并建立逐项对照，P3 对每项执行原生 Canvas 与 SDK 同场景对照，才能宣称完整覆盖。原生 Canvas 可持有任意 Rust 状态并访问 Window/App，不等于插件可得到宿主对象、闭包或执行任意宿主应用代码。

插件批量提交绘制数据和受管资源句柄；宿主负责真实 GPUI 调用。文字布局由宿主权威生成，测量批量化并缓存，不在每帧回调中同步等待插件。正确映射准备、命中与绘制阶段，不因跨进程把旧尺寸数据当新尺寸绘制。

画面、命中、逻辑光标及资源归属必须属于同一有效代次。新的完整画面可替换队列里的过时完整画面；增量保持基线链。超重时先优化可见范围、缓存、合批及后台准备，仍超过预算才整幅拒绝并提示，保留上一幅仍有效画面或显示宿主提示；合格新画面可恢复。

不靠丢半份指令拼画面，不把普通滚动、缩放或偶发慢帧直接判为故障，也不缩减绘图种类或闲置卸载。旧画面对应的动作已经失效时不得继续触发旧操作；已确认输入独立保存在宿主。

### C11 光标、输入法、主题与语言

- SDK 支持的文字、标准控件和自定义 UI 提交普通的文本/交互语义后，默认接入当前全部全局光标特效，无需为效果再写适配。静态文字标签不会自动变成可编辑控件。
- 自定义交互仍需定义焦点、文本、逻辑光标、选区及命中含义；SDK 自动提供对应布局、坐标和宿主状态接入，不能从任意图片像素猜出编辑语义。
- 宿主本地维护必要文字状态、字素与布局映射及 IME 查询缓存；输入不逐键等插件往返。逻辑光标/IME 锚点与动画位置分开，滚动、裁剪、缩放及重排后代次同步。
- 所有网格按焦点和模式切换输入法：普通/可视模式、列表和确认等命令区域停用组合；插入、搜索、命令行、路径/文件名等文本区恢复用户当前系统输入法。离开时取消未确认预编辑，并在下一个键前完成切换。
- 普通控件默认使用宿主主题语义色、字体、基础字号及缩放；自绘可取同一信息并保留局部样式。系统 DPI 和用户缩放分开处理；变化只更新受影响布局/画面，不重启插件或启用未启用模块。
- 管理界面默认英文；插件业务文案跟随编辑器语言，提供英文基础资源及可选翻译，缺失逐条回退英文。SDK 通用控件译文由宿主提供，业务文案由作者提供；用户文件、代码、输入和原始工具输出不自动翻译。
- 带字母助记键的字符按钮遵守项目约定：各语言文案用 `&` 标注 ASCII 字母，方括号包裹，只有助记字母用 Key 样式下划线；渲染和匹配共用解析结果，同窗唯一，大小写不敏感。搜索的 Enter/Esc 按键标签则按既定整段键名下划线处理。

初版不要求系统读屏及辅助技术桥接；这不取消键盘、IME、文本交互语义或光标要求。

### C12 插件管理、安装、更新与清理

管理入口为 Space 后接 Shift+P，使用编辑器现有的字符网格、主题和遮罩。顶部是带标题的筛选框。`[1] Installed | [2] Marketplace | [3] Local ZIP` 放在列表上边框，已安装和市场列表按名称、版本、状态分列。按 `/` 或点击筛选框进入输入，显示 `[✓ Enter]`、`[✕ Esc]` 并给键名下划线。确认保留筛选，取消恢复进入搜索前的查询和选中项。文本输入期间暂停管理命令。

列表下方带标题的两行虚线框显示选中项简介，溢出省略。`?` 打开快捷键帮助。Enter 用 `xxx Details` 替换列表，q/Esc 返回并保留列表状态。详情页签为 Overview、Modules、Activation rules、Logs。模块列表显示作用域、状态，底部两行给原因。只有诊断能确定具体原因时才显示细节。

查看静态清单、普通设置、帮助、模块状态或保留数据，不为展示信息额外启动插件。Overview 展示轻量运行概况，详细采样按需，Logs 有界保存。

| 操作 | 已确认行为 |
| --- | --- |
| 市场来源 | 初版只有官方目录和本地 ZIP；当前用本地 JSON 测试目录，没有在线市场建设或第三方投稿后台 |
| 安装选择 | 选择可获取、兼容宿主及平台/必需能力的最新稳定包；无兼容包说明原因 |
| 检查更新 | 仅核心启动完成后、打开 Marketplace 两个时机；后台读取，不周期轮询，不额外 Check Updates，不监视本地市场 JSON 自动刷新 |
| 执行更新 | 用户主动 Update；发现更新只提示，不能自动替换。准备完成后等待在途写入等收尾 |
| 暂缓 | 等待更新时可 Later；等待卸载时可取消，不为了赶期限强行切换 |
| 接管前失败 | 在副本中验证迁移；启动/迁移失败恢复上一兼容可用包及对应状态，宿主最新输入不被旧快照覆盖 |
| 接管后失败 | 先按运行恢复处理，不自动用更新前快照覆盖新数据，不声称回退外部副作用 |
| 卸载 | 停止新调用，等待操作收尾，删除宿主管理的程序/下载包副本及不再共享的可重建缓存；默认保留设置、规则、草稿和登录信息 |
| 清理入口 | 已卸载插件详情的 Install 旁提供 Clear local data；Installed 底部折叠 Retained data 分组可找回入口 |
| 清理范围 | 用户选择已列出的本机设置/普通业务草稿等可清理数据；不删除项目 `.nb/`、模块规则及其草稿/已应用恢复记录、用户原始 ZIP/工具、其他插件数据或仍需核对的操作记录；规则内容仍在 Activation rules 管理 |
| 凭据清理 | 默认不选；用户明确选择后清理，只有凭据残留也保留入口，失败显示剩余内容 |

上一包作为磁盘备份，不要求同一插件常驻两个 runtime。验证阶段不能发起会影响真实用户数据的迁移副作用，再假装靠回退可撤销。没有可用兼容旧包或状态副本时如实报告无法回退。

仅核心恢复、离线、市场读取失败时，本地已安装插件与清理入口仍应可用；本地 JSON 记录不是网络已连通或安装已成功的证据。

### C13 权限、项目执行与原生工具

安装时集中列明并确认文件、网络、工具执行等所需能力；更新新增权限再确认，日常不重复询问。权限声明、实际运行授权、API 兼容及实验许可是不同检查，不能互相替代。

新项目是否允许执行项目脚本另作一次明确选择，记录在本机，不能由项目配置自行授予。拒绝只影响执行相关功能，读文件判断仍按已有访问范围工作；工具没有可核实的安全模式时，不擅自启动会执行项目代码的模式。

外部工具由宿主下载/解包、校验、放入专用目录并管理启动、通信、停止及资源归属，也允许指定已有工具路径。不修改全局 PATH 或系统工具版本；不删除用户自行安装的程序。

兼容的工具文件可共享，进程共享按工具和工作区要求决定。项目关闭释放独占资源；可安全重建的后台服务单独恢复并同步当前未保存正文，普通一次性工具结束、格式化失败、提交或部署不自动重做。

初版工具按编辑器已有系统权限运行，不主动提权；精细系统沙箱后续再做。编辑器已经高权限运行时不承诺自动降权，原生程序也不受与 WASM 宿主接口相同的系统访问限制。界面必须准确说明这点，不能宣传成完整系统隔离。

### C14 公共解析与可选插件协作

公共解析按相同文档版本、grammar 与解析配置复用基础结果，供高亮、折叠等功能使用，嵌入语言按范围和版本管理。Tree-sitter grammar 有自己的接口，查询/主题/图片是资源；不把所有数据都机械包装成业务 WASM。专有分析可继续由插件自行实现。

不同插件只能通过宿主中转进行可选异步协作，合理批量请求，宿主处理等待、取消、权限及故障。合作方不存在、模块条件不满足或未就绪时返回明确状态，只影响附加能力；不自动安装或绕过规则激活合作方。

已取消必需插件依赖、关联安装、关联卸载、依赖组合更新及统一治理第三方业务服务版本的方案。合作协议由相关开发者负责；宿主 API 的稳定性、插件内部模块、公共解析及原生工具管理不因此取消。

### C15 普通设置、迁移与快捷键

常规设置由插件静态声明名称、类型、默认值、说明和约束，宿主生成控件；复杂设置可用 UI SDK 自定义，但仍通过宿主配置接口提交。普通设置在插件故障或未运行时也能查看和修改。

每项声明能否随项目共享或只在本机保存。可共享项目值写 `.nb/`，项目覆盖全局；本机项按声明可有本机项目覆盖，但不写入项目共享文件。工具路径不一律判成本机项，要允许项目相对路径等共享情况。开发自动编译开关仅本机保存。

Apply 按 C07 生效；只通知实际有效值改变的相关对象，必要时重建最小可安全重建范围，并等待在途写入收尾。主动设置切换不套用或清除崩溃恢复计数。

升级优先兼容读取旧设置。存在可靠等价转换时保留原内容，实际改写配置文件先形成待应用内容；无法转换、删除项或含义变化时保留并提示，不能静默回默认值或扫描改写所有项目。缺省继承继续继承，不冻结成旧默认值。

插件声明公开命令、所属模块、适用上下文和建议键位，宿主统一登记并显示来源、可用状态及实际映射。新默认键不覆盖已有冲突键，用户明确选择优先；不重叠上下文可复用同键，文本输入与输入法优先。

**用户自定义快捷键全局使用，不分项目。** 每个日常/开发配置环境有自己的本机映射，不能写 `.nb/` 或提供项目覆盖层。改键经 Apply 保存并同步帮助，不重启插件；焦点、模式、权限和模块条件仍适用，命令不能触发二次激活门槛。

### C16 凭据与秘密设置

宿主提供异步读取、保存和删除专用凭据接口，使用本机安全存储，按安装绑定的完整身份组合及配置环境隔离。锁定、缺失、取消、拒绝及读写失败分别报告，不降级为明文文件，不阻塞核心启动。

秘密正文不进入普通配置、`.nb/`、草稿、历史、导出或宿主凭据接口日志，不自动跨机器同步。正常卸载保留；同名同 ID 且同环境重装可继续访问有效凭据，但不跳过正常安装许可和系统解锁。本机删除不等于撤销远端授权，也不清理外部工具自己的凭据。

设置页手工填写秘密仍需 Apply。未提交秘密仅保留当前会话内存并遮蔽显示，离开时允许 Apply、继续编辑或放弃，崩溃后需重填。保存新秘密和配置引用必须协调：必要保存失败保留原组合和当前会话输入；不能先覆盖旧秘密，再报告配置没有改变。

专用库与配置文件没有天然跨系统原子事务。E04 需要设计暂存、发布及中断后的核对，避免旧引用指向已被覆盖的秘密；不新增普通秘密历史备份。提交后服务拒绝新密钥则保留新值和错误，不偷用旧值。正常登录及令牌刷新不需每次 Apply。

此接口隔离不保证阻止有本机执行权限的程序绕过宿主，也不保证拿到明文令牌的插件永远不会自行泄漏它。

### C17 SDK 开发流程

SDK 默认启动独立测试编辑器，使用独立配置、安装记录、可写插件数据、草稿及异常记录。开发者显式选择测试项目，可加载本机编译输出并重载，无须每次打 ZIP；普通用户不需要 Rust 编译器。

自动编译与重载在“设置 → 插件 → xxx 插件”中逐插件可选，仅在主动开启的对应开发会话生效；关闭后手动构建/重载，结束会话停止监听。**初始关闭是 E07 建议，尚非用户指定的默认值。**

只加载最新完整成功构建；编译失败保留运行版本。重载保留宿主输入、等待副作用操作、失效旧代次，重新核对权限/实验契约，不自动 Apply 规则，不绕过故障或内存暂停。普通安装仍手动更新，市场 JSON 不因开发监听自动刷新。

独立配置环境不是操作系统沙箱，选中的真实项目仍可被修改。不得默认复制工作区或声称测试实例不会影响 `.nb/`、构建文件及 Git 状态。具体窗口沿用当前编辑器交互；会话中另外讨论的文件浏览界面变更不改写插件管理页的 `/` 搜索约定。

### C18 调度、内存、缓存与诊断

交互优先，后台加载、编译、索引和受管工具限量并行，其他项目持续推进。大量文件事件合并为有界刷新批次，可短暂显示 Updating；持续变化也要持续处理，普通小变动及时更新。用户编辑及操作结果不能当作可丢弃刷新事件；`.nb/` 仍需 Apply，市场仍只在两个时机读取。

内存统计包含插件 runtime、工具及其造成的宿主队列/图像/布局等占用；共享资源单独计账，不能把共享映射重复累加。先清可重建缓存并限制新增分配，仍无法控制时停止最小可行超限对象，保留正文和已确认输入，暂停该对象自动重启并给用户处理入口。这不是闲置回收。

可重建磁盘缓存有总容量预算，清较久未用且当前未占用的条目；当前使用者保留引用。项目文件、配置、规则、草稿、凭据、操作核对记录和更新回退备份不在自动缓存淘汰范围。再次打开旧项目可能重建索引，正文先可编辑。

基础监测持续低成本运行：可关联插件/模块/作用域，分别记录排队、计算、I/O、编译、初始化、消息、绘制、资源及恢复；详细采样按需且有界。日志不吞掉关键状态，也不能无限增长或泄漏秘密。

并发数、内存额度、磁盘预算、队列/帧限额、文件事件合并窗口及重建收尾时限属于 E05/E06，必须测量后形成默认值，不凭空宣布达标。安全结束与“操作仍待确认”分开报告；预算到期不等于外部副作用已停止。

## 6. 测试方案

这是**工程建议与未来验收设计，尚未执行**。优先从用户能观察的宿主行为验证，避免测试内部容器布局或复制实现逻辑。

建议以“加载一个测试插件、注入项目/文档/输入事件、观察宿主结果”的统一入口覆盖安装身份、规则、Apply、版本化编辑、资源释放与恢复。沿用现有文档和 Vim 的行为验证基础，以及网格帧/键盘路由的测试先例；不为了可测性为每一层再造一个公开入口。

该入口配合可控时钟、文件/存储失败及消息延迟，用于确定性验证。真实插件进程、死循环中断、原生工具、系统凭据适配、GPUI 绘制、中文 IME 和 Release 延迟必须另作真实集成/平台验证，模拟通过不能替代。

验收清单逐项规定阶段、可观察结果与验证方式；所有首版要求有承接阶段。基础用例通过后按风险补边界，不反复启动无关全量测试。每个完成记录必须包含环境、产物/提交、方法、结果与未覆盖项，不使用研究文档中的历史测试数代替本次结果。

## 7. 不在本次首版要求中的内容

- 必需插件依赖、依赖链自动安装/卸载/组合更新、宿主统一治理第三方业务服务版本。
- 项目指定插件版本、项目级个人快捷键、模块按闲置时间回收、首次使用才启用的第二道门槛。
- 当前建设在线市场、第三方投稿后台、多市场源、定时自动检查或自动更新插件。
- Git 产品界面、更多底部窗口/分栏布局；任意只读虚拟文档/远程文件系统并未由相关例子获采纳。
- 首版系统读屏桥接、精细操作系统沙箱、任意 GPUI 原生应用对象或任意 2D/3D/shader 能力。
- 任意外部操作恰好一次执行或完整回滚、系统掉电耐久性、由插件草稿机制推导的正文跨宿主崩溃历史系统。
- 自动承诺所有平台验收通过、所有历史版本无限可运行、完全相同的原生绘制性能。

已暂缓或否决的内容不自动进入“后续必做”。日后扩大范围需有新依据。
