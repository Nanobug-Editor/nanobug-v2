# 插件系统实机验收

从 `nanobug` 主工作区运行验收。构建时使用同一份源码生成编辑器和插件运行时。测试使用专门的项目和配置目录。各项验收条件见[分阶段验收清单](插件系统分阶段验收.md)。

## Windows 真冷启动

当前 Windows 工作区的 `test-output/windows-cold-current` 已准备三轮，每轮四个场景。使用这台电脑时直接从重启开始。换到另一台机器时，先用下面的命令准备四种场景和相应插件缓存。只想先验证一轮可以加 `-Rounds 1`。

```powershell
cd C:\Projects\RustProjects\nanobug
.\plugins\runtime\tests\windows_cold_start.ps1 -Prepare -Fixture .\test-output\windows-cold-current
```

保存手头工作，从 Windows 开始菜单选「重启」。每次登录后先运行下面的命令。测完再打开编辑器或双击试用包。脚本会根据系统的启动时间拒绝同一次开机的重复样本。每次只跑一个场景，依次是零插件、50 个插件无匹配、50 个插件中 10 个活跃，以及 10 个活跃但插件编译缓存未准备。Windows 重启会执行完整启动流程。[Microsoft 关于重启和快速启动的说明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail)

```powershell
cd C:\Projects\RustProjects\nanobug
.\plugins\runtime\tests\windows_cold_start.ps1 -Fixture .\test-output\windows-cold-current
```

回传 `test-output/windows-cold-current/cold-results/` 和 `binaries.json`。四次重启可得到第一轮可用数据。样本较少时逐次报告耗时，积累足够轮数后再核对 1 秒 P95。脚本可在普通 PowerShell 运行，使用 Codex 自带的 Python，也可加 `-Python` 指定 Python 3 的路径。遇到失败保留该次记录，下次重启后继续。

## macOS Apple Silicon

将这份工作区的源码或随附源码包带到 Mac，在登录后的桌面打开终端。在源码根目录运行。需要 Rust、Apple 开发工具和可用的 Metal。用 `xcrun -sdk macosx -find metal` 检查是否有 Metal 编译器。安装了完整 Xcode 但缺 Metal 工具链时，可按 Apple 的说明安装该组件。[Apple 的 Xcode 组件说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)

```bash
mkdir -p test-output/macos-acceptance
sw_vers > test-output/macos-acceptance/system.txt
uname -m >> test-output/macos-acceptance/system.txt
set -o pipefail
cargo build --locked --release -p nanobug -p nanobug-plugin-runtime \
  2>&1 | tee test-output/macos-acceptance/build.log
cargo test --locked --release -p nanobug --bin nanobug sdk_canvas_matches_native_metal_pixels -- --ignored --test-threads=1 --nocapture \
  2>&1 | tee test-output/macos-acceptance/metal-pixels.log
cargo test --locked --release -p nanobug --lib corevideo_surface_preserves_y_and_chroma_rows -- --test-threads=1 \
  2>&1 | tee test-output/macos-acceptance/corevideo.log
NANOBUG_ATLAS_CYCLES=240 cargo test --locked --release -p nanobug --test macos_svg_atlas -- --run \
  2>&1 | tee test-output/macos-acceptance/atlas.log
cargo test --locked --release -p nanobug-plugin-runtime --test native_tools_linux \
  2>&1 | tee test-output/macos-acceptance/tools.log
cargo test --locked --release -p nanobug-plugin-runtime --test session repeated_rust_and_vue_lifecycle -- --test-threads=1 --nocapture \
  2>&1 | tee test-output/macos-acceptance/lifecycle.log
cargo test --locked --release -p nanobug --lib native_vault_is_profile_scoped_and_keeps_only_references_on_disk -- --ignored --test-threads=1 --nocapture \
  2>&1 | tee test-output/macos-acceptance/keychain-profile.log
NANOBUG_MAC_KEYCHAIN_CANCEL=1 cargo test --locked --release -p nanobug --lib macos_temporary_keychain_reports_native_failures -- --ignored --test-threads=1 --nocapture \
  2>&1 | tee test-output/macos-acceptance/keychain-status.log
```

最后一条出现 `Nanobug-acceptance.keychain` 解锁弹窗时，点「取消」。它使用临时钥匙串。如果 `tools.log` 提示缺 Python 3，用 `command -v python3` 找到可用的路径，以 `NANOBUG_TEST_PYTHON=/绝对路径/python3` 开头重跑工具测试。回传 `test-output/macos-acceptance/`、`test-output/plugin-canvas-parity-macos/` 和显示缩放。没有 Metal 编译器但有 SDK 时，可在 `cargo build` 或 `cargo test` 的 `--` 之前加 `--features gpui_platform/runtime_shaders` 先验证。保留采用该方式的记录，默认的 Metal 编译构建也需要补测。

用下面的命令打开一个临时项目，复制随源码包提供的 `fixtures/workspace-panel.zip` 到项目里的 `测试插件.zip`。本机归档的示例包位于 `test-output/plugin-p0-archive-20261113/test-output/plugin-final-gates-nov13/canvas-en/workspace-panel.zip`。

```bash
fixture=$(mktemp -d "${TMPDIR:-/tmp}/nanobug-acceptance.XXXXXX")
mkdir "$fixture/project"
printf 'sample\n' > "$fixture/project/README.md"
cp fixtures/workspace-panel.zip "$fixture/project/测试插件.zip"
target/release/nanobug --plugin-dev-profile "$fixture/profile" \
  --plugin-trace "$PWD/test-output/macos-acceptance/editor-ime.jsonl" "$fixture/project"
```

1. 切换到系统简体拼音。依次按 `Space`、`Shift+P`、`3`、`Enter`，打开只显示目录和 ZIP 文件的文件选择器。按 `f` 进入筛选，用拼音选词输入「测试」，再按 `Enter` 应用筛选。选中 `测试插件.zip` 后按 `Enter` 进入安装审查，按提示确认安装。
2. 按 `1`、`/` 打开已安装列表的搜索。用拼音选中一个中文候选。按 `Esc` 后立刻按 `q`，记录是否直接关闭管理器。重开搜索，输入 `ni`，看到候选后先按一次 `Esc`。记录这一键只取消候选还是也关闭搜索。关闭搜索后的第一个 `q` 应退出管理器。再开一次搜索并选词，确认拼音仍然可用。
3. 清除搜索后进入 `Workspace Panel` 详情，打开 `Modules` 并进入自绘面板。输入一个确认的中文字符，记录文字及光标是否显示，退回正文后按 `i` 并选一个中文字符。按 `Esc`、`Ctrl+s`，核对 `README.md` 只增加了确认的文字。回传 `editor-ime.jsonl` 和两次 `Esc` 的观察结果。

## Linux 原生 Wayland

如果手头有 Linux 桌面，用同一源码构建编辑器和插件运行程序，将上面的临时项目和键盘步骤再跑一遍，回传 `editor-ime.jsonl`、发行版、桌面或合成器名称、输入法名称。尤其记录确认候选后紧接 `Esc`、`q` 的表现，以及有未确认候选时第一次 `Esc` 的表现。Sway 上的 Fcitx 与 IBus 正在选词时会接走第一次 `Esc`。可以再按一次 `Esc`，或直接点搜索框的 `[✕ Esc]`，等搜索框关闭后再按 `q`。[GPUI Linux 输入法记录](../vendor/gpui-pre-linux/NANOBUG.md)

有原生 Linux 桌面和实际显卡时，用以下命令验证 DRM 驱动的显存走势，回传 `ATLAS_*` 行。`ATLAS_BEGIN` 应显示实际适配器且 `software_emulated` 为 `false`。WSLg 已通过 RTX 5080 上的资源回收与 DXCore 显存采样。

```bash
NANOBUG_ATLAS_CYCLES=1200 NANOBUG_ATLAS_KEYS=48 cargo test --locked --release \
  -p nanobug --test linux_svg_atlas -- --run
```
